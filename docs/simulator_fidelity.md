# 시뮬레이터 충실도: 같은 SMT2020인데 결과가 다르다

작성: 2026-11-04 (리서치 에이전트 조사 + 코드 직접 확인)

## 요약

- 같은 SMT2020 데이터를 시뮬레이터마다 다르게 구현해서, **처리량은 거의 같은데 사이클타임(CT)이 크게 갈린다.**
- 우리 EDA 01의 동적 수치는 **원판 PySCFabSim**에서 나왔다. 이 시뮬레이터는 2년 실행에서 기준값보다 CT가 20~50% 길었다.
- 가장 유력한 원인은 **배치 시작 규칙**이다. 원판은 배치가 최대치로 꽉 찰 때까지 기다린다. 다만 다른 변경과 섞여 있어서 배치 효과만 따로 떼어 보지는 못했다.

## 원판 vs 리팩터링판 vs 기준값

출처: Heik, Leißau, Reichelt 외, "Implementing the SMT2020 Wafer Fab Data Sets Using Different Simulation Packages" (IEEE TSM 투고 초안, 원문 미공개). 원자료는 [Zenodo 15798604](https://zenodo.org/records/15798604)이고, 리서치 에이전트가 결과표를 직접 열어 읽었다. ACT 단위는 일로 추정했다.

| HV/LM, FIFO, 2년 | Kopp/Mönch 기준 | PySCFabSim 원판 | 리팩터링판 |
|---|---|---|---|
| 일반 lot ACT (제품 3 / 4) | 51.2 / 28.4 | **76.9 / 44.0 (+50%)** | 52.5 / 28.8 |
| 일반 lot 납기 준수 | 91% / 90% | **0%** | 78% / 86% |
| 총 처리량 | 39,480 | 38,383 (−2.8%) | 39,377 (−0.3%) |

| LV/HM, CR | 기준 | 원판 | 리팩터링판 |
|---|---|---|---|
| 일반 lot ACT 제품 1 / 5 | 47.7 / 22.0 | 56.7 / 28.4 (+19~29%) | 47.8 / 22.2 |
| 총 처리량 | 약 39,573 | 38,903 (−1.7%) | 39,536 |

- 장비 가용률, 고장·PM 비율, 가동률은 원판과 리팩터링판이 거의 같다(차이 1%p 안팎).
- AnyLogic 구현(DS1)은 처리량이 기준과 +0.1% 차이지만 hot lot 납기 준수가 9.9%로 크게 다르다. hot lot 납기 정의가 달랐을 가능성이 있다.

## 원인 후보

1. **배치 규칙** [코드 직접 확인]
   - 원판: `external/PySCFabSim/simulation/greedy.py:50` `if len(lots) < batch_max: lots = None`. 최대 배치가 찰 때까지 투입하지 않고, 최소 배치(BATCHMN)는 사실상 무시한다. 같은 step끼리만 묶고 제품은 섞을 수 있다.
   - SMT2020 원 사양(WSC 2019): "최대보다 1 lot 적어도 투입 허용"
   - AnyLogic: "같은 제품 + 같은 step, 웨이퍼 수 min~max"
   - 리팩터링판: `Max` / `Min` / `RoundRobin` / `Demand` 전략 4종(`simulation/greedy.py:101-108`). 보고된 결과는 `Demand`(최소 이상이면 투입, 최대에서 자름)로 돌린 것으로 보인다.
2. **초기 WIP와 warm-up**: 리팩터링판은 AutoSched 초기 WIP를 반영하고 1년 뒤 통계를 초기화했다(커밋 메시지).
3. **기타**: CQT 처리 비활성화, 리워크 수정, 데이터셋 수정(커밋 메시지).
4. **PySCFabSim 개발자 본인의 언급**(ASMC 2022 슬라이드): "디스패칭 파라미터 설정", "문서화되지 않은 기능 → 다른 구현"

추가로 원판에서 발견한 것: 최소 연속 처리(implant 7 lot) 규칙이 `dispatch_failed < 5`일 때만 지켜진다(`greedy.py:61`). 다섯 번 실패하면 규칙을 무시한다.

## Shibata 2026 (Zenodo P-30)

- 원문은 찾지 못했다. 제목("배치 구성 정책이 불충분하게 정의되어 CT가 민감")만 있고 수치는 없다.
- 30회 반복 KPI는 확보했다. LV/HM_E로 추정되고, 처리량 68.5~68.8 lot/일, 평균 CT 약 37일, 반복 간 편차가 매우 작다.
- 사양 공백 1건이 명시돼 있다. PM과 고장이 겹칠 때 처리 방법이 사양에 없다.

## 우리 작업에 주는 영향

- **EDA 01의 동적 분해**(대기 48%, 확산 배치 대기 4.6%, 영역별 대기 배분)는 원판 PySCFabSim FIFO, 180일, 시드 1개 결과다. 원판의 배치 규칙 때문에 편향됐을 수 있다. **정적 분석**(EDA 01 1절, EDA 02)은 시뮬레이터와 무관하므로 영향이 없다.
- **확산로 배치 결정의 레버**는 "작다"고 결론 내리기 이르다. 배치 규칙 하나로 CT가 수십 % 바뀔 가능성이 있다(다른 변경과 혼재).
- **확인 방법**: 리팩터링판에서 다른 조건은 고정하고 배치 전략 4종만 바꿔 돌린다. 그러면 배치 정책의 순수 효과를 잴 수 있다.
