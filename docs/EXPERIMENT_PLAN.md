# 실험 계획과 평가 규칙 (팀 공통)

작성 2026-11-13. 실험을 돌리거나 결과를 표로 만들 때는 이 문서를 따른다. 바꾸고 싶으면 먼저 팀에 말하고 이 문서를 고친 뒤 실험한다(결과를 보고 규칙을 바꾸면 그 사실을 보고서에 적어야 한다).

## 0. 결정된 것

- 주제: implant 가스 교체 RL (Implant_128, 132, 91). 데이터셋 HVLM.
- 알고리즘: DQN, PPO 직접 구현 (`experiments/dqn_implant.py`, `ppo_implant.py`). SB3는 교수님 답을 받기 전까지 참고용으로만.
- 비교 기준: cov(압력 규칙). lssu(공장 기본)는 맥락용으로 같이.
- 환경: 공장 도착 기록 재생(`src/`). 보정 결과는 README "오차 보정".
- 보상: R1 = −(대기 lot 수 × 시간 + 교체 시간) ÷ 장비 수. 바꾸지 않는다.
- 상태(s): **우리 29개로 통일**(팀 결정 2026-11-13). 기본 23개 + 앞 공정 lot 수 6개(`src/implant_state.py`). 학습·평가 모두 앞 공정 정보 있음이 기본이고, `--no_upstream`(6칸을 0으로)은 대안 비교로만 쓴다.
- 아직 정할 것: 기다리기 방식(다음 사건까지 / 10분). → E1로 정한다.

## 2. 실험 목록과 시드 수

시드 수는 질문의 무게에 맞춘다. 신뢰구간으로 "낫다"고 주장하는 것은 최종 주 결과뿐이다.

| # | 실험 | 목적 | 학습 시드 | 평가 |
|---|---|---|---|---|
| E1 | 기다리기 방식: 다음 사건까지 vs `--wait_min 10` | a 확정 | 2~3 | 검증 점수로 결정, 시험은 보고 |
| E3 | **최종 주 결과**: 확정 설계(s 29개, 앞 공정 있음)로 DQN, PPO | 주장 | **알고리즘당 10 (DQN, PPO 같게)** | 시험, 3절 전부 |
| E4 | 민감도: `nstep_h` 0.25/0.5/1, `explore_switch` 0.01/0.02/0.05 (DQN) | 하이퍼파라미터 영향 | 2~3 | 시험, 평균과 범위만 |
| E5 | 대안 비교(ablation): 앞 공정 정보 없음(`--no_upstream`), 다단계 목표 없음(`--nstep_h 0`), 탐색 기준점 없음(`--explore_switch` 빼기), PPO argmax 평가 | 설계 근거 | 2~3 | 시험, 평균과 범위만 |
| E6 | 공장 검증: E3에서 검증 점수로 고른 DQN 1개 | 공장 지표 | - | 4절 |

- 왜 주 결과는 10개인가: v4에서 시드별 전체 개선 폭의 표준편차가 약 3.4%p라, 95% 구간 반폭이 시드 5개면 약 ±4.2%p, 10개면 약 ±2.4%p다. 개선 폭(전체 약 −2%, 128 약 −7%)이 작아서 5개로는 cov와 구분이 안 된다. PPO도 같은 수로 맞춘다(최종 설계에서 PPO가 cov 근처로 올라올 수 있고, 알고리즘 비교에 같은 노력을 들이기 위해).
- 앞 공정 정보 없음(E5)은 v4에서 이미 DQN·PPO 각 5개씩 있다(`*_noup_*_v4`). v4 DQN: 검증 점수 평균 0.845(없음) 대 0.843(있음), 시험 전체 cov 대비 −3.3% 대 −4.2%, Welch p=0.62로 차이 없음. 최종 설계(E1 결과)가 v4와 다르면 2~3개로 다시 돌린다.
- 2~3개짜리 실험(E1, E4, E5) 규칙: (1) 설정 간 검증 점수 차이가 잡음(약 ±0.05)보다 작으면 결정하지 않는다. 시드를 3개로 늘려 보고, 그래도 비슷하면 더 단순한 쪽이나 팀이 이미 정한 쪽을 고른다. (2) 보고서에는 "시드 n개, 평균(최소~최대)"로 쓰고 신뢰구간·"유의하게 낫다"는 쓰지 않는다. 그런 표현은 E3에만.
- 학습 1회: DQN 약 15분, PPO 약 20분(4개 동시 기준). 공장 2년 1회 약 2시간.
- 결과 파일 이름 규칙: `--suffix`로 실험을 표시하고 시드는 `_s<번호>`로 끝나게 둔다(분석 스크립트가 끝의 `_s<번호>`를 떼서 조건을 묶는다). 예: `--suffix _e1w10` → `dqn_noup_e1w10_s0.pt`.

### 기본 설정 (v4, 지금까지 가장 좋은 것)

```bash
# DQN
python3 experiments/dqn_implant.py --steps 600000 --explore_switch 0.02 --nstep_h 0.5 [--no_upstream] [--wait_min 10] --suffix _<실험> --seed <s>
# PPO
python3 experiments/ppo_implant.py --iters 300 --lam 0.95 --lam_time --lr_decay --wait_init 0.99 --ent 0.003 --ent_end 0 --eval_sample [--no_upstream] [--wait_min 10] --suffix _<실험> --seed <s>
```

왜 이 설정인지(결정이 촘촘한 SMDP에서 탐색·목표를 시간 기준으로 맞춘 이유)는 `docs/implant_rl_design.html` 5절.

## 3. 평가 지표 (최종)

### 3-1. 주 지표: lot당 지연 D

- **정의:** D = lot이 implant 앞에서 기다린 시간 + 그 lot 때문에 생긴 가스 교체 시간 (시간). 낮을수록 좋다. 보상 R1과 같은 양을 lot당으로 나눈 것이다.
- **측정 대상:** 60~220일에 도착한 lot. 시뮬레이션은 기록 끝(약 240일)까지 돌려서 측정 대상이 다 처리되게 한다.
- **장비군별 3개 + 전체 1개**(세 장비군을 lot 수로 가중).
- **cov 대비:** 같은 시나리오(같은 도착, 같은 고장 시드)에서 짝지은 비율 `D_RL / D_cov − 1`을 시나리오 10개에 대해 평균 → **학습 시드당 1개 값**.
- **신뢰구간:** 조건(알고리즘, 대안 비교면 설정)마다 따로, 학습 시드 값들로 t 95% 구간(E3은 10개). 조건끼리 섞지 않는다(예: 앞 공정 유무는 시드가 아니라 비교 대상).
- **개선 확률 P(RL < cov):** (학습 시드 × 시나리오) 짝 중 `D_RL < D_cov`인 비율. 구간은 학습 시드를 다시 뽑는 부트스트랩.
- **lssu 대비**도 같은 방식으로 같이 보여 준다(개선 폭의 크기를 가늠하는 맥락).
- **두 조건 비교**(예: DQN 대 PPO, 앞 공정 유무): 학습 시드 값들로 Welch t (시드끼리는 짝이 아니다).
- **공장에 넣을 정책 1개:** 주 단위 짝 차이(정책 D − cov D)를 4주씩 묶어(주끼리 독립이 아니어서) 부트스트랩 95% 구간.

### 3-2. 굶기기 확인 (주 지표가 믿을 만한지)

- **미처리 lot 수:** 측정 대상인데 끝까지 처리를 시작 못 한 lot. 0이어야 한다.
- **리틀 법칙 대기 ≈ 실제 대기:** 시간 평균 대기 lot 수(재공) ÷ 도착률이 처리한 lot의 평균 대기와 같아야 한다. 차이가 크면 어떤 lot이 굶고 있다는 뜻이다.
- 둘 중 하나라도 어긋나면 D를 그대로 보고하지 말고 원인을 먼저 본다.

### 3-3. 보조 지표 (다른 것을 희생했나)

| 지표 | 왜 |
|---|---|
| 지연 95% 지점 | 평균은 좋은데 일부 lot이 아주 오래 기다리지 않나 |
| hot lot 지연 | 급한 lot이 늦어지지 않나. 단, hot lot이 있으면 RL이 아니라 cov가 결정하므로 RL의 **간접** 효과로 해석 |
| 교체 시간 비율, 장비당 하루 교체 수 | 교체를 남발하거나 지나치게 참지 않나 |
| RL이 내린 결정 비율 | 결정 중 RL이 고른 것과 cov가 대신 처리한 것(hot lot, 가스 없음)의 비율 |
| 처리량(하루 처리 lot) | 측정 기간 처리량이 cov와 같아야 한다 |

### 3-4. 알고리즘 비교용

- **학습 곡선:** 가로축은 환경 step 수(PPO와 DQN을 같은 축에), 세로축은 검증 점수(시드 1, cov = 약 0.95). 결과 json의 `log`에 있다. 시험 데이터로 그리지 않는다.
- 학습 1회 시간(참고, 기계마다 다름), 하루 결정 수(기다리기 방식 비교 설명용, 성능 지표 아님).

### 3-5. 공장 지표 (E6)

- **주 지표: 공장 안 implant 대기**(장비군별). 공장 시드 4·5·6에서 cov와 짝지어 비교.
- implant X-factor = (대기 + 처리 시간) ÷ 처리 시간.
- 공장 평균 CT, 납기 준수율. **CT는 잡음이 크다**(시드 간 표준편차 약 0.45일, cov도 implant 대기 −45%에 CT −2.6%이고 구간이 0을 포함)고 미리 밝힌다. 시드 3개라 방향만 본다.
- 주의: 지금 공장 검증은 세 장비군에 정책을 동시에 넣는다. 다른 implant 장비군을 거쳐 돌아오는 lot(12시간 안에 128의 18%, 91의 25%)은 작은 환경에서는 기록 시각에 도착하므로, 공장 결과와 작은 환경 결과가 다를 수 있다. 해석에 적는다.

### 3-6. 환경 신뢰도 (보고서 환경 절)

- `calibration/diagnose.py --fab_downs`: 같은 시드·기간·규칙으로 공장 기록과 재생 비교. 대기, 교체 수, 연속 처리 길이, 가동률, 주간 짝 차이 구간.
- `calibration/check_fidelity.py`: 규칙을 바꿨을 때 공장과 같은 만큼 움직이는지.

## 4. 돌리는 순서 (명령)

```bash
# (1) 학습: 2절 표의 실험마다
python3 experiments/dqn_implant.py ... --suffix _<실험> --seed <s>

# (2) 시험 평가: 시나리오별 지표를 results/eval/에 저장 (lssu, cov도 같은 시나리오로 한 번 저장)
python3 experiments/evaluate.py --kind dqn --models "results/rl_dqn/dqn_*_<실험>_s?.pt" [--wait_min 10]
python3 experiments/evaluate.py --kind ppo --stoch --models "results/rl_ppo/ppo_*_<실험>_s?.pt" [--wait_min 10]

# (3) 표 만들기: 조건별 D, cov 대비 %와 t 구간, lssu 대비, 굶기기 확인
python3 experiments/analyze.py
python3 experiments/analyze.py --compare <조건A> <조건B> --selected <정책 파일 이름>

# (4) 비교 기준만 따로 보기 / cov 튜닝 다시 확인
python3 baselines/run_baselines.py
IMPLANT_FEEDBACK=1 python3 experiments/run_implant_replay.py tune

# (5) 공장 검증 (시뮬레이터 필요: ./setup_simulator.sh)
python3 experiments/pick_policy.py           # 검증 점수로 정책 고르기
bash experiments/run_fab_final.sh
```

- 학습 중 저장되는 `result_*.json`의 시험 표는 빠른 확인용이다. **보고서 숫자는 (2)(3)으로 만든다.**
- 평가 방식이 바뀌면(이 문서 3절) 기존 모델도 (2)(3)을 다시 돌려 같은 방식으로 맞춘다.
